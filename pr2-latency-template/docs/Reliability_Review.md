# Проверка реализации ПР3

Выполнена самопроверка кода и автоматические тесты. Это не ревью другого участника команды.

- В ReliableChannel нет сокетов. Сохраняются исходные байты команды, время и число отправок.
- ACK снимает только pending. Повторный, неизвестный или поздний ACK не создаёт новый результат.
- Последней попытке даётся полный RTO; затем появляется единственное событие failed.
- Для RTT после retransmission применяется правило Karn. PONG и ACK первой попытки обновляют один AdaptiveTimeout.
- RTTVAR использует предыдущий SRTT; коэффициенты 1/4 и 1/8, пределы RTO 100..3000 мс.
- Флаг requiresAck проверяется по типу до чтения payload. Усечённые, старые и лишние байты отвергаются.
- Дедупликация разделена по IP:port; проверены переупорядочивание, старые номера и переход через 65535.
- В рамках сессии клиент не переиспользует номера, поэтому старый ACK не подтвердит новую команду.
- Реальными UDP-тестами проверены потерянный ACK, ложный ACK, чужой адрес, повреждённый пакет, повтор команды и отсутствие сервера.
- Журнал проверяется независимо: одна итоговая запись на команду, согласованность числа повторов, границы RTO.
- Все 300 команд эксперимента подтверждены; по серверным логам каждая применена ровно один раз.

Локально: Catch2 — 24 сценария, 291 проверка; также интеграционные Python-тесты ПР2/ПР3 и запуск одной командой.
