# Подсистема телеметрии UDP

Цель: завершить C++17-шаблон ПР №2, провести реальные UDP-измерения,
сохранить воспроизводимый эксперимент и подготовить репозиторий к проверке.

## Границы модулей

- protocol: явные операции big-endian, заголовок 7 байт, PING 15 и PONG 31 байт;
  проверка длины, типа, версии, payloadSize и границ до чтения payload.
- telemetry: автомат состояний с передаваемым монотонным временем в us,
  ограниченная история, experiment ID, attempts=1, метрики и события.
- transport: RAII UDP IPv4-сокет, select, адрес отправителя, steady_clock.
- client/server: CLI, координация модулей, CSV, неблокирующий планировщик PONG.
- scripts: реальные серии, независимый пересчёт метрик и графики из CSV.

## Состояния

pending -> received либо pending -> timeout -> late_response.
После received/late_response повтор даёт duplicate_response.
Номер сверяется вместе с echoed client timestamp: старый PONG не завершает
новый PING после повторного использования uint16. Неверные метки, чужой адрес
и повреждённые пакеты не влияют на успешные метрики.
Deadline включительно: age >= 1 000 000 us. Поздний ответ не отменяет потерю.
Pending не вытесняется; завершённые записи вытесняются в порядке регистрации.
Если весь ограниченный контейнер занят pending, новая регистрация отклоняется.

## Статистика

RTT = clientReceiveUs-clientSendUs. Серверные часы только для диагностики.
SRTT первого ответа = RTT, далее 0.875*SRTT+0.125*RTT.
Jitter = среднее абсолютных разностей соседних успешных RTT в порядке приёма.
Loss = timeouts/sent. Для пустой серии RTT отсутствует, jitter для n<2 равен 0.
CSV содержит итоговые строки received/timeout и отдельные диагностические события.

## Эксперимент и проверка

6 серий x 50 PING, интервал 200 ms, timeout 1000 ms, loopback.
Серверный эмулятор с mt19937/фиксированным seed: baseline; +50 ms; +100 ms;
U[50,150] ms; Bernoulli 5%; 100+U[-50,50] ms и Bernoulli 5%.
Seed фиксирует воздействия, а вариации планировщика ОС сохраняются.
Catch2 проверяет байты/ошибки/арифметику/состояния/границы/переполнение.
Интеграционные тесты используют реальные UDP-сокеты и процессы.
